# 视频缓存状态化改造设计

## 目标

修复详情页下载按钮在 Android 13+ 通知权限已授权时不响应的问题，并让下载进度同时出现在 App 内和通知栏。下载必须使用当前选中的集数；离线缓存页应展示排队中、下载中、失败、已完成状态，并支持失败任务重试。

## 约束

- 保留现有 Java + Android Views 技术栈，不引入新的任务框架。
- 后台下载继续使用前台服务和持续通知。
- 下载任务串行执行，避免现有 Service 的并发停止和通知覆盖问题。
- 状态持久化到应用私有 `SharedPreferences` JSON；任务记录量小，不引入 Room 迁移。

## 组件

### DownloadTask

持有任务 ID、视频 ID、集数、标题、下载 URL、封面、进度、状态、文件路径、错误信息和更新时间。任务 ID 由视频 ID 与集数组成，同一集重复点击不会创建重复任务。

### DownloadTaskStore

线程安全地读写任务 JSON。它是详情页、缓存列表和服务共同使用的状态来源，并提供查询、更新、删除和按更新时间排序能力。

### ServiceDownload

接收完整任务参数，将任务标记为排队并放入单线程队列。执行时更新持久化状态、发送仅限本应用的状态广播，并同步更新前台通知。最后一个任务结束后停止前台状态和服务。

### VideoDownloader

保留分片并行下载，但整个调用同步等待分片完成后再合并。失败只回调一次；临时文件按任务隔离，成功后删除临时目录。

### 详情页

下载按钮始终注册监听器。Android 13+ 可请求通知权限，但权限结果不阻止下载。使用当前 `currentPlayingIndex` 对应 URL 和集数。页面显示水平进度条与状态文字，并在切换集数时刷新对应任务状态。

### 离线缓存页

列表以持久化任务为主，同时兼容扫描旧的已完成缓存文件。每项显示标题、状态和进度；已完成项点击播放，失败项点击重试，长按删除任务及文件。

## 状态流

`QUEUED → DOWNLOADING → COMPLETED`，异常时进入 `FAILED`。下载中或排队中的任务可进入 `PAUSED`；继续时重新进入 `QUEUED`，复用已完成分片并从原进度继续。重试将 `FAILED` 重新置为 `QUEUED`。所有更新先写入任务仓库，再广播给可见 UI；通知栏读取同一进度值。

## 验证

- 强制完整构建和 lint。
- 在已连接的 Android 16/API 37 模拟器安装应用。
- 验证通知权限已开启时按钮仍注册并启动服务。
- 验证当前集 URL/文件名来自 `currentPlayingIndex`。
- 验证状态存储、广播、详情页进度和缓存页进度资源均连接。
- 通过 logcat 检查服务启动、任务状态更新及崩溃。
